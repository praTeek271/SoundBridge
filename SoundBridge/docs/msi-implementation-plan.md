Current implementation includes:

- WiX MSI packaging under `installer\`.
- Product metadata loaded from `app.meta.json`.
- Product name and executable name: `SoundBridge`.
- Stable `UpgradeCode` loaded from `app.meta.json -> installer.upgradeCode`.
- ProductCode strategy is `auto`.
- PackageCode strategy is `auto`.
- `MajorUpgrade` with same-version upgrades allowed for local testing.
- Add/Remove Programs icon through `ARPPRODUCTICON`.
- Privacy agreement dialog.
- Install-scope dialog.
- Optional Desktop shortcut dialog.
- Virtual audio device prerequisite notice dialog.
- Start Menu shortcut always created.
- Desktop shortcut controlled by secure `CREATE_DESKTOP_SHORTCUT`.
- Install scope is per-machine only.
- Backend build, GUI publish, and MSI package in one script.

Before final release of any new MSI, update `product.version` in `app.meta.json`.
Do not rely on same-version upgrade behavior for public releases.

Version policy:

- `product.version` changes only when the project owner explicitly asks.
- `product.displayVersion` must equal `v ` + `product.version`.
- `installer.upgradeCode` stays fixed forever for SoundBridge.
- ProductCode and PackageCode are generated by the MSI toolchain, not manually
  maintained in metadata.

## MSI Strategy

Use MSI only.

Recommended authoring tool:

```text
WiX Toolset
```

Reason:

- MSI is the chosen installer format.
- WiX is suitable for traditional Windows desktop installers.
- It supports Start Menu shortcuts, install directories, uninstall behavior, custom UI, and prerequisite dialogs.
- It keeps us closer to production-quality Windows installer conventions than ad-hoc packaging.

## What MSI Installs

Install app files into:

```text
Program Files\SoundBridge\
```

MSI installs:

- `SoundBridge.exe`
- `SoundBridge.dll`
- `SoundBridgeBridge.dll`
- Runtime files from self-contained publish, if self-contained mode is used.
- `asset\beep.wav`
- App icon resources included in the executable.

MSI creates:

- Start Menu shortcut: `SoundBridge`
- Add/Remove Programs entry: `SoundBridge`
- Optional Desktop shortcut: `SoundBridge`

MSI does not install:

- Virtual audio driver/device.
- User templates.
- `%LocalAppData%\SoundBridge` contents.

## Virtual Audio Device Prerequisite Flow

SoundBridge requires a virtual audio device to route system audio.

For MSI v1:

- The MSI does not install the virtual device.
- The MSI shows a prerequisite notice.
- The user clicks `OK` / `Continue`.
- SoundBridge installation continues.
- The user remains responsible for installing the virtual device separately.

Suggested prerequisite message:

```text
SoundBridge requires a virtual audio device to route system audio.

Please install the recommended virtual audio device before using routing.

This installer will continue with SoundBridge app installation only.
```

Installer behavior:

- The notice should not block installation permanently.
- It should be informational.
- Later, it can include a clickable download link.

App behavior after install:

- On launch, scan available render devices.
- If the virtual device is missing, show setup status in the app.
- Do not start routing automatically.
- Do not change Windows default output during install.

## Persistence and Uninstall Rules

User-created template data lives here:

```text
%LocalAppData%\SoundBridge\
  templates.json
  templates.backup.json
  logs\
    app.log
  corrupted\
```

MSI uninstall should not delete this folder by default.

Reason:

- It contains user-created templates.
- Reinstall should preserve user configuration.
- Removing user data should be an explicit future option, not default MSI behavior.

## Build Pipeline

Run from:

```text
D:\Lucifer-Drive\Programs\Virtual Audio Drive Program\SoundBridge
```

Step 1: Configure backend if needed.

```powershell
cmake -S backend -B backend\build-integration -A x64
```

Step 2: Build backend.

```powershell
cmake --build backend\build-integration --config Release
```

Step 3: Build GUI Release.

```powershell
dotnet build app\SoundBridge.Gui.csproj -c Release
```

Step 4: Publish GUI for installer input.

Recommended for installer:

```powershell
dotnet publish app\SoundBridge.Gui.csproj -c Release -r win-x64 --self-contained true -o dist\SoundBridge
```

Step 5: Build MSI from:

```text
dist\SoundBridge\
```

Current MSI build script:

```powershell
.\installer\build-msi.bat
```

The batch file runs `build-msi.ps1` with process-local execution policy bypass
so normal Windows PowerShell policy does not block the build.

If WiX is not installed:

```powershell
dotnet tool install --global wix
wix extension add WixToolset.UI.wixext
```

Expected MSI output:

```text
dist\installer\SoundBridgeSetup.msi
```

## Known Decisions

- MSI only.
- No MSIX.
- No Inno Setup.
- No driver installation inside MSI v1.
- Virtual audio device is user-managed.
- SoundBridge checks for devices at runtime.
- Template persistence remains per-user JSON under `%LocalAppData%`.
- Product metadata is stored in `app.meta.json`.
- Start Menu shortcut is always created.
- Desktop shortcut is optional and selected by checkbox.
- Install scope is selected by the user during installer UI.
- Privacy agreement is shown first with an `I agree` checkbox.
- Virtual-device notice has no required `I understand` checkbox for now.
